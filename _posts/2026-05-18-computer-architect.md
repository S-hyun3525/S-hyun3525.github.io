### 8ch 캐시 기억 장치
주기억 장치에 저장되어 있는 명령어와 데이터 중의 일부를 임시로 복사하여 저장하는 장치.
데이터를 저장하고 인출하는 속도가 주기억 장치보다 빠르다.
고속 완충 기억 장치 라고도 한다.

### 기억장치의 구성
- 기억 장치의 계층 구조를 따르는 기억 장치의 구성은 다음과 같다.
	- 주기억 장치
		- 입출력 프로세서
			- 자기 테이프
			- 자기 디스크
		- cpu
			- 레지스터 - 캐시기억장치
		- 캐시 기억 장치
			
- 계층적으로 구성된 기억 장치는 참조의 특성을 이용하여 동작.
- 기억 장치를 참조할 때도 10%에 해당하는 특정 영역만 참조하는데, 이것을 참조의 지역성(Locality of Reference)라고 한다.

### 참조의 지역성
- 시간 지역성
	- 설명: 최근에 접근한 데이터나 명령어는 곧 다시 접근될 가능성이 높음
	- ex) for, while, 루프 안의 변수
- 공간 지역성
	- 설명 : 현재 참조한 메모리 주소와 인접한 주소들도 곧 참조될 가능성이 높음
	- ex) 배열 순차 접근 array[i], array[i+1]
- 순차 지역성
	- 설명: 메모리를 순차적으로 접근하는 경향
	- ex): 코드 실행 흐름에 따라 다음 명령어를 순차 실행

### 캐시 기억 장치의 동작 
- 주기억 장치는 외부의 보조 기억 장치에 저장된 프로그램을 저장하는 장치로, CPU, 보조 기억 장치 간의 속도 차이를 극복하기 위해 사용 됨
- 주기억 장치는 보조 기억 장치보다 빠르지만 CPU에 비하면 매우 느리다.
- 이에 주기억 장치보다 빠른 저장 장치로 캐시 기억 장치가 등장하게 되었다.

- 캐시 기억 장치는 5~100나노초 정도로 접근 시간이 빠른 기억 장치이다.
- 수행할 명령어나 피연산자를 주기억 장치에서 가져와 저장하고 있다가 빠른 속도로 CPU에 제공한다
- cpu와 주기억장치 사이에 위치한다.
- 캐시 기억 장치가 없는 컴퓨터 시스템의 cpu는 프로그램의 명령어를 실행할 때마다 주기억장치에 직접 접근하여 명령어와 필요한 정보를 인출해야함
- 캐시 기억 장치가 포함된 컴퓨터 시스템의 경우 cpu가 명령어 또는 데이터를 인출하기 위해 주기억 장치보다 캐시 기억 장치를 먼저 조사한다.
- 명령어를 찾았을 때를 HIT(적중), 명령어가 없어서 찾지 못했을 때를 MISS(실패)f라고 한다.
- 실패의 경우
	- cpu가 1000번지의 워드를 필요로 한다고 가정할때 캐시 기억장치의 실패과정을 단계별로 나타내어보자
> 1 :  cpu가 캐시 기억 장치에 요청
> 2 : 캐시기억장치는 없으므로 주기억 장치에서 가져온다.
- 적중의 경우
> 1: ''
> 2: 캐시 기억 장치에 존재한다면 바로 워드를 cpu에 반환

캐시 기억 장치는 cpu가 수행할 명령어와 필요한 정보를 저장하고 있다가 필요시 즉시 제공하여 신속하게 처리되도록 한다.
이러한 동작은 프로그램 내장형 컴퓨터의 특성인 **기억 장치 참조의 지역성**에 의해 가능

캐시 기억 장치의 적중 
- 캐시 기억 장치의 동작 순서를 알아보자
1. 시작
2. cpu에서 주소 전달
3. 캐시기억 장치에 명령어가 존재 하는가?
	3.1  no : 명령어를 포함한 주기억 장치에 접근
	3.2 주기억 장치에서 명령어 블록 인출
	3.3 주기억 장치의 명령어 블록을 캐시에 저장
	3.3 명령어 단어를 cpu에 전송
4. yes : 획득한 명령어를 cpu에 전송
5. Fin

### 적중률
- 캐시 기억 장치가 있는 컴퓨터의 성능을 나타내는 척도
- 적중률이 높을수록 캐시 기억 장치의 속도가 빠름
- 적중률 계산 법 : 적중횟수 / 전체 메모리 참조 횟수 
- 주기억 장치와 캐시 기억 장치에서 데이터를 인출하는 데 소요되는 평균 기억 장치 접근 시간을 분석하여 정략적 성능을 확인해보기
- T~avarage~ = H~hit_ratio~ * T~cache~ + ( 1 - H~hit_ratio~) * T~main~
> T~avarage~ : 평균 기억 장치 접근 시간
> T~hit_ratio~ : 적중률
> T~cache~ : 캐시 기억 장치 접근 시간
> T~main~ : 주 기억 장치 접근 시간
- 기억 장치 접근 시간을 감소시키려면 접근 시간이 빠른 캐시 기억 장치의 적중률이 높고, 접근 시간이 많이 느린 주기억 장치의 실패율이 낮아야 함
- 평균 기억 장치 접근 시간은 캐시 기억 장치의 적중률이 높을수록 캐시 기억 장치 접근 시간에 근접함으로써 컴퓨터의 처리 속도가 빨라진다.

- 캐시 기억 장치를 설계하려면 다음의 요소를 고려해야함
	- 캐시 기억 장치의 크기
	- 인출 방식
	- 사상 하수
	- 교체 알고리즘
	- 쓰기 정책
	- 블록 크기
	- 캐시 기억 장치의 수 등

### 캐시 기억 장치의 크기
- 캐시 기억 장치의 용량이 증가한 만큼 속도가 향상되지는 않음
- 캐시 기억 장치는 주기억 장치보다 고가이므로 용량증가가 비용 상승으로 이어짐
- 캐시 기억 장치의 용량과 주변 회로 간의 복잡도 관계를 최적화하여 적중률을 향상하고 접근 시간이 저하되는 것을 막는 정도의 용량을 결정해야함.
- 1~128k 워드가 최적이라고 알려짐

### 인출 방식
- 요구 인출(Demand Fetch)방식
	- cpu가 현재 필요한 정보만을 블록 단위로 주기억 장치에서 인출해오는 방식
	- 장점 : 불필요한 데이터 인출을 방지 > 효율적인 저장공간 사용
	- 단점 : cpu가 필요로 하는 시점에 인출하므로 지연(latency)가 발생 가능
- 선인출(Prefetch) 방식
	- cpu가 현재 필요한 정보 외에도 앞으로 필요할 것으로 예측되는 정보를 미리 인출하여 캐시 기억 장치에 저장하는 것.
	- 주기억 장치에서 명령이나 데이터를 인출할 때 필요한 정보와 이웃한 위치에 있는 정보를 함께 인출
		- 장점 : cpu가 요구하는 명령이나 데이터가 일정 프로그램 구간에 집중되는 경우(지역성이 높은 경우)에 효과가 좋음
		- 단점 : 동시에 인출하는 정보의 블록이 커지면 한꺼번에 많은 정보를 읽어올 수 있지만, 블록 인출 시간이 길어짐
> 블록이 커질수록 캐시 기억 장치에 적재할 수 있는 블록의 수가 감소하기에 블록이 더 빈번히 교체됨, 블록의 크기는 4~8개 워드가 적절

### 사상(mapping)함수
- 다음은 주기억 장치와 캐시 기억 장치의 구조를 비교하여 보여줌
- 주기억 장치의 용량이 2^n^개의 워드이고 블록이 K개의 워드로 구성된다면 블록의 수는 **2^n^/K** 로 계산됨
- cpu가 프로그램을 실행할 때, 캐시 기억 장치에 저장된 명령어의 인출이 모두 끝났거나 분기 명령어에 의해 캐시 기억 장치에 저장되어 있지 않은 명령어를 모두 인출하고자 하는 경우 캐시 기억장치에서의 인출이 실패함.
- 캐시 기억 장치에서의 인출이 실패하면 캐시 기억 장치의 일부분을 주기억 장치로 옮기고 **주기억 장치에서 필요로 하는 정보를 캐시 기억 장치에 기억**시키는 정보 교환이 이루어짐
- 주기억 장치와 캐시 기억 장치 사이에 정보를 옮기는 것을 사상이라고 함
- 다음은 사상의 개념을 나타낸 것으로, 주기억 장치에서 캐시 기억 장치로 새로운 워드가 전달 되는 과정을 보여줌.

- 직접 사상(DIRECT MAPPING)
	- 주기억 장치의 블록이 캐시 기억 장치의 특정 라인에만 적재될 수 있어 캐시 기억 장치의 정중 여부를 판단하기 위해 그 블록이 적재될 수 있는 라인만 검사하는 방식.
	- 직접 사상에서는 주 기억 장치의 주소 형식이 3개의 필드로 구성됨
	>T : 태그필드 S : 슬롯필드 W:워드 필드
	
	- 직접 사상에서 주 기억 장치의 블록 j 가 적재될 수 있는 캐시 슬롯의 번호 i는 다음과 같이 모듈러 (MOdulo) 연산에 의해 결정됨 (m은 캐시 슬롯의 전체 수)
	> i = j mod m

	- 모듈러 연산은 다음과 같이 나머지를 구하는 연산으로 설명 가능 (Q는 몫이고 R은 나머지)
	> J/m = Q+R , R=i
